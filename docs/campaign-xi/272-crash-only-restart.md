# Slice 272 — Crash-only restart

**Date:** 2026-10-09 · **Tests:** `tests/test_chaos_crash.py` (6 tests, slow-marked, green)

## What existed before

`CheckpointJournal` was *designed* crash-safe (atomic tmp+fsync+
`os.replace`, CRC-protected records, torn reads ignored) — but
nothing had ever proven it. Crash-only design is a claim that must
survive a real SIGKILL, not a code review.

## What was built

**`hugrgate/chaos/crash.py`** (new module, exported from
`hugrgate.chaos`):

- **`CrashOnlyHarness`** — spawns a worker subprocess
  (`python -m hugrgate.chaos.crash worker <dir> <count>`) writing
  ordered checkpoints `{"counter": n}` in a tight loop, SIGKILLs
  it after `kill_after_s`, reaps it (no zombies), then recovers
  via `CheckpointJournal` in the parent and verifies:
  recovery succeeds; the recovered checkpoint is the newest
  *completed* write (a killed mid-write is invisible by
  construction); torn `.tmp` files ignored. Returns a
  JSON-serializable **`CrashReport`** (`killed`,
  `recovered_counter`, `checkpoints_valid`, `torn_tmp_files`,
  `recovered_cleanly`).
- **`worker_main(directory, count)`** — the worker entrypoint,
  also unit-testable in-process.

## Verification

- 6 tests, all `pytest.mark.slow` (deselected by default):
  torn/corrupt/alien records ignored by `recover()`; worker
  writes ordered counters; **real SIGKILL mid-write recovers
  cleanly** (recovered counter is a write prefix, no gaps);
  no zombie processes across runs; bad arguments rejected;
  three consecutive kill cycles on one directory stay consistent
  (sequence numbers keep increasing, no reuse).
- `ruff check` clean; import-cycle and API-inventory gates
  green.
- **Correction folded into slice 270's commit** (fixup): the
  degradation plan's cache-miss raised `LookupError`, which the
  error-taxonomy raise-site gate rejects — changed to `KeyError`
  (precise for a cache miss, in the gate's allowed set).
- The API inventory doc (`docs/campaign-i/003-public-api-inventory.md`)
  was regenerated by `test_inventory_doc_is_fresh`'s sanctioned
  mechanism (234→249 modules, 1429→1550 names) and is committed
  here — this also explains the two "transient" failures in
  slices 270/271: they were the drift detector firing on the
  stale doc, not flakes.
